# Обновление работающей панели: интеграции с плагинами, аккаунты, ответы в тикетах и автодополнение

Эта инструкция — про **обновление уже установленной панели**, а не про первую
установку. Первая установка — в [`DEPLOY.md`](DEPLOY.md); сюда переходят, когда
панель уже работает на `manage.aurumgg.ovh` и нужно выкатить то, что появилось
после того, как вы собрали первую версию companion-плагина.

Инструкция рассчитана на человека, который редко работает с сервером. Как
подключиться по SSH, что такое `sudo` и как редактировать файлы — в разделе
[«Мини-ликбез»](DEPLOY.md#мини-ликбез-если-вы-редко-работаете-с-сервером)
основной инструкции.

---

## Главное про живую систему

На серверах играют люди прямо сейчас. Поэтому:

| Что делаем | Кого задевает |
| --- | --- |
| Обновление панели на VDS | панель недоступна ~10 секунд; игровые сервера **не трогаются вообще** |
| Замена jar companion-плагина | нужен **перезапуск игрового сервера** — игроков выкинет |
| Установка LuckPerms / EssentialsX / InvSee++ / Vault | тоже перезапуск игрового сервера |

Отсюда важное следствие: **это два независимых обновления, и делать их можно
в разное время.** Панель после обновления работает и со старым jar плагина:
всё, что шло через RCON, работает как раньше, автодополнение по Tab —
по собственному списку команд панели, а на вкладке «Группа прав» будет
написано, что companion-плагин не ответил. Ничего не ломается. Так что панель
обновляйте хоть сейчас, а игровой сервер перезапускайте, когда на нём будет
пусто.

Ничего из перечисленного не трогает WireGuard-туннель, правила фаервола,
Pterodactyl, конфиг nginx, порты и `config.yml` самого плагина.

## Что нового и что из этого требует действий

| Что появилось | Что нужно сделать |
| --- | --- |
| Права игрока через LuckPerms, инвентари офлайн через InvSee++, валюта через Vault, автоопределение плагинов сервера | новый jar плагина + сами плагины на сервере |
| Быстрые действия, сгруппированные по плагинам (EssentialsX) | ничего, появится само |
| Создание сотрудников Админом, письма с временным паролем, онбординг, внутренние сообщения | миграция БД + настроить SMTP |
| Ник — единственное имя сотрудника; отображаемые имена убраны из системы | миграция БД, дальше само (см. ниже) |
| Смена своего пароля и ника в «Настройках», сброс пароля сотруднику от ГМ | ничего, появится само |
| ASCII-арт: ассистент присылает его коллеге, чат показывает моноширинным | ничего, появится само |
| Карточка игрока вместо трёх разрозненных экранов, объявление через `/title` | ничего, появится само |
| Ответы на тикеты приходят игроку лично, с заметным префиксом | ничего, работает на ванильных командах |
| Автодополнение по Tab в консоли | базовый уровень — сам; продвинутый — новый jar плагина |

### Про имена сотрудников

Раньше у сотрудника было два имени: отображаемое (его задавал ГМ при создании
аккаунта) и ник (человек выбирал сам при первом входе). Осталось одно — **ник**.
Отображаемые имена удаляются миграцией, отдельных действий не требуется.

Что меняется на глазах:

- в форме создания сотрудника больше нет поля «Отображаемое имя» — только email
  и роль;
- у кого ник ещё не выбран (человек ни разу не входил), в «Доступах» видно
  «`почта` · ник ещё не выбран»;
- **владелец панели получает ник `GM`** — он единственный, кто не проходит
  первый вход, и до этого обновления его вообще не было в списке адресатов
  внутренних сообщений: написать ему было нельзя. Если ник `GM` уже кем-то
  занят, миграция возьмёт прежнее отображаемое имя владельца.

Ник владельца потом меняется как обычно — «Настройки» → блок «Ник»; у ГМ на это
разрешение постоянное.

## Порядок

1. **Шаг 1.** Бэкап.
2. **Шаг 2.** Обновить панель на VDS.
3. **Шаг 3.** Проверить, что панель поднялась.

7. **Шаг 7.** Проверить всё новое по чек-листу.

Шаги 1–4 безопасны в любое время. Шаги 5–6 требуют перезапуска игрового сервера.

## Шаг 1. Бэкап

Обязательно: шаг 2 меняет структуру базы.

```bash
sudo systemctl start aurum-backup.service
sleep 20
ls -lh /var/backups/aurum-panel/ | tail -3
```

### Что должно получиться

Свежий файл `.dump` с сегодняшней датой и ненулевым размером:

```
-rw-r----- 1 aurum aurum 214K Aug 17 03:10 panel_2026-08-17_03-10-42.dump
```

### Если не получилось

Файла нет или он пустой:

```bash
sudo systemctl status aurum-backup.service --no-pager
sudo journalctl -u aurum-backup.service -n 30 --no-pager
```

Чаще всего это `.pgpass` — доступ к базе для бэкапа настраивается в
[шаге 6.1](DEPLOY.md#61-настроить-доступ-к-базе-для-бэкапа) основной
инструкции. **Не идите дальше без рабочего бэкапа**: миграцию можно откатить
только восстановлением из дампа.

## Шаг 2. Обновить панель на VDS

Подключитесь к VDS (`ssh root@83.168.69.151` или ваш способ) и выполняйте
по одной команде.

```bash
cd /opt/aurum-panel
```

**2.1. Забрать новый код.**

```bash
sudo -u aurum git pull
```

> **Сначала проверьте, что тянете нужную ветку.** `git pull` забирает ту
> ветку, на которой сервер стоит сейчас (обычно `main`). Если изменения ещё
> лежат в отдельной ветке и не влиты, `git pull` честно ответит
> `Already up to date.` — и дальше вы пересоберёте ровно то же, что было.
>
> Посмотреть, где вы:
>
> ```bash
> sudo -u aurum git branch --show-current
> sudo -u aurum git log --oneline -1
> ```
>
> Если нужная ветка не влита в `main`, влейте её через pull request на
> GitHub — и только потом `git pull` на сервере. Переключать рабочую копию
> сервера на ветку вручную не стоит: потом легко забыть, что панель живёт не
> на `main`.

**2.2. Пересобрать.** `prisma:generate` обязательно **до** `build` — сборщику
нужны типы Prisma, иначе увидите два десятка ошибок TypeScript.

```bash
sudo -u aurum npm ci
sudo -u aurum npm run prisma:generate
sudo -u aurum npm run build
```

Это самая долгая часть — 2–5 минут, машина будет занята.

**2.3. Применить миграцию базы.**

```bash
cd /opt/aurum-panel/apps/api
sudo -u aurum env $(grep -v '^#' /etc/aurum-panel/api.env | grep -v '^$' | xargs) \
  npx prisma migrate deploy
```

**2.4. Перезапустить.**

```bash
sudo systemctl restart aurum-api
```

### Что должно получиться

На шаге 2.3 применятся все накопившиеся миграции по очереди:

```
Applying migration `20260817000000_accounts_mail_messages`
Applying migration `20260818000000_palworld_bans`
Applying migration `20260819000000_ai_assistant`
Applying migration `20260820000000_nickname_only`
All migrations have been successfully applied.
```

Если написано `No pending migrations to apply` — значит, они уже были
применены раньше. Это нормально, идите дальше.

> **Одна из миграций необратима.** `20260820000000_nickname_only` **удаляет**
> колонку `display_name` из `users`: отображаемые имена сотрудников убраны из
> системы, именем остаётся только ник (подробности — в разделе
> [«Про имена сотрудников»](#про-имена-сотрудников) выше). Перед этим она
> проставляет ник владельцу панели.
>
> Откатить её можно **только восстановлением из дампа**, поэтому шаг 1 —
> не формальность. Учётные записи, пароли, роли и привязки серверов при этом
> не меняются: удаляется одно поле, и то после того, как из него спасено имя
> владельца.

Остальные миграции только **добавляют** — новые колонки и таблицы
(`staff_messages`, `app_settings`, баны Palworld, таблицы ассистента).

### Если не получилось

**`error: Your local changes would be overwritten by merge`** на шаге 2.1 —
на сервере правили файлы руками. Посмотрите, что именно:

```bash
sudo -u aurum git status
sudo -u aurum git diff
```

Если правки не нужны — `sudo -u aurum git checkout -- .` и повторите `git pull`.
Если нужны — сохраните файл в сторону и потом верните.

**Ошибки TypeScript на шаге 2.2** — почти всегда `prisma:generate` не отработал.
Выполните его отдельно и посмотрите на вывод:

```bash
cd /opt/aurum-panel
sudo -u aurum npm run prisma:generate
```

**`Environment variable not found: DATABASE_URL`** на шаге 2.3 — не подхватился
файл настроек. Проверьте, что он на месте и читается:

```bash
sudo ls -l /etc/aurum-panel/api.env
sudo grep -c DATABASE_URL /etc/aurum-panel/api.env   # должно быть 1
```

**Сервис не поднялся** после 2.4:

```bash
sudo systemctl status aurum-api --no-pager
sudo journalctl -u aurum-api -n 50 --no-pager
```

Откат — в конце этой инструкции.

## Шаг 3. Проверить, что панель поднялась

```bash
curl -s http://10.0.0.1:3001/api/health/ready
```

### Что должно получиться

```json
{"ready":true,"checks":{"database":"ok","redis":"ok"}}
```

Затем откройте `https://manage.aurumgg.ovh` в браузере и войдите. Если экран
выглядит по-старому — обновите страницу с очисткой кэша: **Ctrl+Shift+R**
(на Mac — **Cmd+Shift+R**). Браузер держит старый JavaScript, и без этого вы
увидите прошлую версию интерфейса.

Признак, что новая версия приехала: в левом меню появился пункт
**Сообщения**.

### Если не получилось

**`"ready":false` с `"database":"fail"`** — не поднялась база:
`sudo systemctl status postgresql`.

**`"redis":"fail"`** — не поднялся Redis: `sudo systemctl status aurum-redis`.
Если он в цикле перезапусков — смотрите
[раздел про Read-only file system](DEPLOY.md#если-уже-словили-read-only-file-system).

**502 в браузере** при живом `health/ready` — nginx смотрит не туда либо не
перечитал конфиг: `sudo nginx -t && sudo systemctl reload nginx`.

**Страница логина вместо панели, ошибок нет** — у вас протух токен сессии.
Просто войдите заново.

## Шаг 4. Настроить почту (SMTP)

Новые сотрудники теперь получают временный пароль **письмом**, поэтому без
почты приглашения не работают. Ваш собственный вход это никак не затрагивает.

Панель отправляет письма через **обычный SMTP** — подойдёт почтовый ящик на
вашем домене. Сторонние сервисы рассылок не нужны.

Меню **Настройки** (виден только ГМ) → блок **Почта (SMTP)**:

| Поле | Что писать |
| --- | --- |
| Сервер | SMTP-хост вашего почтового хостинга, например `mail.aurumgg.ovh` |
| Порт | **587** (STARTTLS) в большинстве случаев; **465**, если хостинг требует SSL |
| Логин | полный адрес ящика, например `panel@aurumgg.ovh` |
| Пароль | пароль этого ящика |
| Отправитель | `Aurum Panel <panel@aurumgg.ovh>` |

Нажмите **Проверить соединение** — она проверяет логин и шифрование, ничего
не отправляя.

Пароль ящика хранится зашифрованным тем же ключом `APP_ENCRYPTION_KEY`, что и
RCON-пароли, и не отдаётся наружу ни в одном ответе API.

### Что должно получиться

Зелёное «Соединение с SMTP установлено».

### Если не получилось

- **«SMTP отверг логин или пароль»** — дело в учётных данных ящика, а не в
  панели. Проверьте их в почтовом клиенте.
- **«Не удалось соединиться»** — либо неверный хост/порт, либо исходящий 587
  закрыт у хостера VDS. Проверьте с самого VDS:
  ```bash
  timeout 5 bash -c 'cat < /dev/null > /dev/tcp/mail.aurumgg.ovh/587' && echo открыт || echo закрыт
  ```
  Если закрыт — попробуйте порт 465, а если и он закрыт, вопрос к хостеру VDS.
- **Соединение есть, а письма уходят в спам** — нужны SPF и DKIM у домена.
  Их TXT-записи выдаёт почтовый хостинг вместе с ящиком, добавить их надо в
  DNS. Панель на это не влияет: она лишь отдаёт письмо вашему SMTP-серверу.

Если почту настроить не выходит, аккаунты всё равно создаются — панель честно
скажет, что письмо не ушло, и временный пароль можно выдать повторно на экране
**Доступы**.

## Шаг 5. Пересобрать плагин и заменить jar

**Здесь потребуется перезапуск игрового сервера — игроков выкинет.**
Делайте, когда на сервере пусто, или предупредите заранее (в панели:
блок быстрых команд → **Объявление** — крупная надпись на весь экран у всех).

Обновлённый плагин добавляет: список установленных плагинов, работу с правами
через LuckPerms, инвентари офлайн-игроков через InvSee++ и настоящее
автодополнение команд по Tab.

**5.1. Собрать новый jar на своём компьютере.** Инструкция та же, что и в
прошлый раз: [`companion-plugin/BUILD-WINDOWS.md`](../companion-plugin/BUILD-WINDOWS.md).
Порядок не изменился, но начните с обновления исходников — иначе соберёте ту
же самую старую версию:

```powershell
cd $HOME\aurum
git pull
cd companion-plugin
.\gradlew.bat clean :paper:jar
```

Готовый файл — там же, где и в прошлый раз:

```
%USERPROFILE%\aurum\companion-plugin\paper\build\libs\AurumCompanion-0.1.0.jar
```

Открыть папку в проводнике: `explorer paper\build\libs`.

> **Проверьте дату файла.** Версия в имени не изменилась, поэтому старый и
> новый jar выглядят одинаково. `clean` в команде выше как раз для того,
> чтобы не перепутать: он удаляет прошлую сборку, и в папке остаётся только
> свежий файл.

> Сборке нужен интернет: она докачивает Paper API, LuckPerms API с Maven
> Central и **VaultAPI с jitpack.io**. Первая сборка после обновления будет
> чуть дольше обычной. Токенов ни для того, ни для другого репозитория не
> нужно.

**5.2. Заменить jar на игровом сервере.** Pterodactyl → сервер → **Files** →
папка `plugins`:

1. Удалите **старый** `AurumCompanion-0.1.0.jar`.
2. Загрузите новый (имя файла то же — поэтому старый надо именно удалить,
   иначе загрузка может не перезаписать его).
3. **Restart** сервера.

> **`config.yml` не трогайте.** Формат настроек не менялся: тот же токен, тот
> же порт, тот же адрес панели. Плагин при обновлении конфиг не перезаписывает.

### Что должно получиться

В консоли сервера после запуска:

```
[AurumCompanion] HTTP-сервер companion слушает 10.0.0.2:8085 — порт не должен быть доступен из интернета
```

Если вместо этого `Не удалось занять порт …` или `HTTP-сервер не запущен: …` —
смотрите «Если не получилось» ниже.

**Проверка 1 — плагин вообще доступен.** С VDS (адрес и порт — ваши из
`config.yml`):

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://10.0.0.2:8085/players
```

**401** — плагин отвечает и требует токен; это правильный ответ, связь есть.
**000** — плагин недоступен: не запустился, не тот порт или закрыт фаервол.

**Проверка 2 — приехала ли новая версия.** Отличить новый jar от старого можно
только запросом с токеном: без токена оба отвечают одинаково — 401.

Токен вводится вслепую и передаётся curl через стандартный ввод — так он не
попадёт ни в историю команд, ни в список процессов (`ps` виден и другим
пользователям машины). Скопируйте все три строки целиком:

```bash
read -rsp 'Токен плагина: ' T; echo
printf 'header = "Authorization: Bearer %s"\n' "$T" |
  curl -s -K - "http://10.0.0.2:8085/complete?line=gam"; echo
unset T
```

Новый плагин ответит списком подсказок — примерно так (состав зависит от того,
какие плагины стоят на сервере):

```json
{"suggestions":["gamemode","gamerule"]}
```

Старый ответит `{"error":"Неизвестный маршрут"}` — значит, заменился не тот
файл либо сервер не перезапускался: вернитесь к пунктам 5.1–5.2.

Ответ `{"error":"Неверный токен"}` означает, что токен вы ввели не тот —
возьмите его из `plugins/AurumCompanion/config.yml` на игровом сервере.

### Если не получилось

**В консоли `Unsupported api-version` или плагин не грузится** — jar собран
не под ту версию Paper. Сверьте версию сервера и пересоберите.

**`Address already in use`** — порт занят. Либо старый экземпляр плагина ещё
живёт (сервер не до конца перезапустился), либо порт занял кто-то другой.
Полный **Stop**, подождать, **Start**.

**Плагин работает, но панель его не видит** (в блоке «Поддерживаемые плагины»
красная надпись про companion-плагин) — панель ходит по адресу из **своих**
настроек, а не по тому, что записано в `config.yml` плагина. Проверьте, что
они совпадают: панель → карточка сервера → вкладка **Настройки** → блок
**Companion-плагин** → адрес вида `http://10.0.0.2:8085` и тот же токен.

**Не хотите перезапускать сервер сейчас** — не перезапускайте, вернитесь к
этому шагу в удобный момент. Со старым jar не будет прав через LuckPerms,
офлайн-инвентарей и подсказок от самого сервера; вкладка «Группа прав» скажет,
что плагин не ответил. Всё остальное — тикеты, баны, whitelist, консоль,
автодополнение по списку команд панели — работает.

## Шаг 6. Поставить LuckPerms, EssentialsX, InvSee++, Vault (по желанию)

Панель ничего из этого не требует — она сама проверяет, что установлено, и
показывает только то, что реально заработает. Ставьте то, что нужно вам.

| Плагин | Что даёт в панели |
| --- | --- |
| **LuckPerms** | вкладка «Группа прав» в карточке игрока: смена группы и отдельные права, через API плагина, а не командами |
| **EssentialsX** | быстрые действия: вылечить, бессмертие, полёт, выдать кит, режим игры, телепорт |
| **InvSee++** | инвентари игроков, которых **нет в сети** |
| **Vault** | блок **Валюта** в карточке игрока (начислить/списать) и общий баланс сервера в статистике |

Ставятся как обычные плагины: скачать jar → Pterodactyl → **Files** →
`plugins` → загрузить → **Restart**.

> **Vault одного мало.** Vault сам денег не хранит — это прослойка. Деньги
> ведёт отдельный плагин экономики, и он должен зарегистрировать у Vault
> провайдера. Если у вас уже стоит EssentialsX, ничего доставлять не нужно:
> его модуль экономики включается сам. Если экономики нет вовсе — поставьте
> любую (EssentialsX, CMI); панель работает с той, что есть, и знать про неё
> ничего не обязана.
>
> Как отличить: панель напишет «Vault установлен, но плагин экономики не
> зарегистрировал провайдера» — значит, не хватает именно плагина экономики,
> а не Vault.

> **Порядок загрузки важен.** Companion-плагин объявляет LuckPerms, InvSee++ и
> Vault «мягкими зависимостями»: он грузится после них. Поэтому если вы
> поставите LuckPerms **позже** companion-плагина, нужен ещё один перезапуск
> сервера — иначе companion его не увидит. Проще ставить всё сразу и
> перезапускать один раз.

### Что должно получиться

Панель → сервер → блок **Поддерживаемые плагины**: напротив установленных
стоит зелёное **есть** с версией, напротив остальных — серое **нет**.

### Если не получилось

**Всё показано как «нет», сверху красная надпись про companion-плагин** —
список плагинов отдаёт именно он. Значит, дело не в LuckPerms, а в
companion-плагине: вернитесь к шагу 5.

**Плагин стоит, а панель пишет «нет»** — сверьте имя. Панель сверяется по
имени, под которым плагин регистрируется в Bukkit, а оно нередко другое:
EssentialsX зовётся **Essentials**, InvSee++ — **InvSeePlusPlus**, Vault так и
зовётся **Vault**. Посмотреть
настоящие имена: ссылка **Показать все плагины сервера** в том же блоке.

**Плагин выключен** (`enabled: false` в списке всех плагинов) — панель считает
его отсутствующим намеренно: командой он всё равно не отзовётся. Смотрите
консоль сервера, почему он не включился.

## Шаг 7. Чек-лист: проверить всё новое

Пройдите по пунктам в браузере. Каждый — одно действие.

**Аккаунты и почта**

- [ ] Меню **Доступы** → создать тестового Модератора → на почту пришло письмо
      с временным паролем.
- [ ] Войти этим паролем в приватном окне браузера → панель требует сменить
      пароль и выбрать **ник сотрудника** и никуда больше не пускает.
- [ ] После онбординга — обычный вход, ник виден.
- [ ] В форме создания сотрудника **нет поля «Отображаемое имя»** — только
      email и роль.
- [ ] В **Настройках** переключатель «Подтверждать аккаунты, созданные
      Админами» на месте (по умолчанию включён).

**Свой ник и свой пароль** *(проверять под обычным сотрудником, не под ГМ)*

- [ ] Меню **Настройки** видно и Модератору; внутри блоки «Ник» и «Пароль»,
      а настройки панели (почта, ассистент, правила аккаунтов) ему не видны.
- [ ] Блок «Ник»: поле заблокировано, написано, что смену открывает ГМ.
- [ ] ГМ в **Доступах** нажимает «Разрешить смену ника» → у сотрудника поле
      разблокировалось → он меняет ник → разрешение погасло само, поле снова
      заблокировано.
- [ ] Блок «Пароль»: смена с неверным текущим отклоняется, с верным —
      проходит, и вход по новому паролю работает.

**Сброс пароля от ГМ**

- [ ] **Доступы** → «Сбросить пароль» у тестового сотрудника → ему пришло
      письмо, и в нём написано про **сброс**, а не про новый аккаунт.
- [ ] Прежний пароль сотрудника больше не работает.
- [ ] Вход по новому временному паролю → панель просит **только новый
      пароль**; ник заново не спрашивается.

**Внутренние сообщения**

- [ ] Меню **Сообщения** → «Написать» → начать вводить ник → **клик по нику в
      подсказке открывает диалог** (раньше не открывал ничего).
- [ ] В подсказках виден **GM** — владельцу панели теперь можно написать.
- [ ] Написать тестовому сотруднику по нику → у него сообщение появляется
      сразу, без обновления страницы.
- [ ] Попросить ассистента: «отправь <ник> ASCII-арт с котом» → появится
      карточка с самим рисунком; после подтверждения он приходит в чат
      **ровным**, моноширинным, без переносов строк.
- [ ] Вставить арт в поле ввода руками (Shift+Enter — новая строка), обрамив
      его строками из трёх обратных кавычек — он тоже покажется ровным.
- [ ] Переписка приватна: под другой учёткой чужого диалога не видно — в том
      числе у ГМ.

**Карточка игрока**

- [ ] Сервер → вкладка **Игроки** → клик по строке игрока открывает карточку.
- [ ] Внутри: здоровье, пинг, мир, координаты; вкладки «Действия»,
      «Инвентарь», «Группа прав».
- [ ] Действия, которым не хватает плагина, показаны **серыми с подсказкой**
      («нужен EssentialsX»), а не спрятаны.

**Ответы в тикетах** *(игрок должен быть в сети — сообщение уходит адресно)*

- [ ] Ответить на любой тикет → игрок получает сообщение **лично**, с золотым
      жирным префиксом `[Поддержка]`, и строку над хотбаром.
- [ ] Соседние игроки этого сообщения **не видят** — это главное отличие от
      прежнего поведения.

**Автодополнение в консоли** *(поле ввода активно только когда консоль Wings
подключилась; если она показывает ошибку, сперва разберитесь с ней — подсказки
прямо на том же экране)*

- [ ] Сервер → вкладка **Консоль** → в поле ввода набрать `gam` и нажать
      **Tab** → дополнилось до `gamemode`.
- [ ] Повторный **Tab** перебирает варианты по кругу, как в игре.
- [ ] Набрать `gamemode creative ` (с пробелом на конце) и нажать **Tab** →
      подставился ник игрока, который сейчас онлайн.
- [ ] Если поставили companion-плагин: под полем подпись **«подсказал
      сервер»**, и в подсказках есть команды ваших плагинов. Без него подпись
      **«по списку команд»** — это нормально, базовый уровень работает всегда.

**Ничего не сломалось**

- [ ] Тикеты, баны, whitelist, консоль Wings работают как раньше.
- [ ] Игроки на серверах играют, лагов нет.
- [ ] `sudo systemctl status aurum-api` — `active (running)`.

## Откат

Если после обновления что-то сломалось.

**Откатить только код** (миграция аддитивная, данные она не портит — обычно
этого достаточно):

```bash
sudo systemctl stop aurum-api
cd /opt/aurum-panel
sudo -u aurum git log --oneline -5        # найдите предыдущий коммит
sudo -u aurum git checkout <хеш-коммита>
sudo -u aurum npm ci
sudo -u aurum npm run prisma:generate
sudo -u aurum npm run build
sudo systemctl start aurum-api
```

**Откатить и данные** — только если миграция реально что-то испортила:

```bash
sudo systemctl stop aurum-api
sudo -u aurum /opt/aurum-panel/deploy/scripts/restore-db.sh \
  /var/backups/aurum-panel/<файл>.dump
sudo systemctl start aurum-api
```

**Откатить плагин** — положить обратно старый jar и перезапустить игровой
сервер. Панель со старым плагином работает: пропадут только права через
LuckPerms, офлайн-инвентари и подсказки от сервера.

Вернуться на новую версию потом: `sudo -u aurum git checkout <ветка>` и снова
пройти шаг 2.

---

## Чего это обновление не касается

Специально, чтобы не искать:

- **Домашний сервер `10.0.0.2`** — кроме замены jar и (по желанию) установки
  плагинов, ничего не меняется.
- **WireGuard-туннель** — не трогается.
- **Правила фаервола** — новых портов не появилось. Автодополнение ходит по
  тому же порту companion-плагина, что и всё остальное.
- **nginx и сертификат** — конфиг не менялся, новых внешних адресов нет.
- **Pterodactyl** — не трогается вообще.
- **`config.yml` companion-плагина** — формат тот же, файл не перезаписывается.
- **Существующие учётные записи, тикеты, баны и whitelist** — миграция только
  добавляет колонки и таблицы.

## Куда смотреть, если что-то пошло не так

```bash
# Логи панели, последние 100 строк
sudo journalctl -u aurum-api -n 100 --no-pager

# Логи в реальном времени — оставьте открытым и повторите действие в браузере
sudo journalctl -u aurum-api -f

# Логи nginx
sudo tail -n 50 /var/log/nginx/error.log
```

Ошибки, видимые только в браузере (консоль **F12** → Console), в логи панели
не попадают — панель в них не участвует. Разбор частых случаев с консолью
Wings есть прямо на экране ошибки во вкладке «Консоль».

Общая шпаргалка по частым ситуациям —
[в основной инструкции](DEPLOY.md#если-что-то-пошло-не-так-общая-шпаргалка).
