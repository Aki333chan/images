# Права в LuckPerms для плагинов Aurum

Настройка трёх групп — `default`, `vip`, `admin` — под AurumGuilds, AurumAuth и
AurumCompanion. Всё, что здесь есть, взято из `plugin.yml` самих плагинов;
несуществующих узлов в инструкции нет.

## Сначала — чего в этих плагинах НЕТ

Чтобы не искать: **ни один игровой узел не придуман под VIP**. Во всех трёх
плагинах вместе объявлено ровно двенадцать прав, и одиннадцать из них
администраторские. Единственный узел, которым VIP отличается от обычного
игрока, — `aurumguilds.create`, и то лишь если включить его проверку в конфиге
(см. ниже).

Это не упущение, а следствие того, как плагины устроены:

- **пати, гильдии, чаты `/p` и `/g`** — возможность для всех, а не привилегия;
- **бонусы гильдии** выдаются гильдии целиком и правом не управляются вовсе —
  их раздаёт панель, админ командой или NPC-торговец через API;
- **тикеты и код входа в панель** (`/ticket`, `/webtoken`) нужны каждому, кому
  есть на что пожаловаться.

Поэтому настоящие отличия VIP — киты, дома, лимиты — живут в EssentialsX и
прочих плагинах, а не здесь.

## Права панели — это не LuckPerms

`minecraft.guilds.manage`, `minecraft.inventory.edit` и остальные `minecraft.*`
— **права сотрудника в панели**, они хранятся в её базе и раздаются ролями на
экране «Доступы». LuckPerms о них ничего не знает, и наоборот.

Из этого следуют две вещи:

1. Сотрудник, у которого в панели есть `minecraft.guilds.manage`, распустит
   гильдию из панели, даже не имея `aurumguilds.admin` в игре.
2. Группа LuckPerms — не роль в панели. Игрок в группе `admin` не получает
   доступа к панели, а сотрудник панели не получает `aurumguilds.admin` в игре.

## Полный список игровых узлов

### AurumGuilds

| Узел | По умолчанию | Что даёт |
| --- | --- | --- |
| `aurumguilds.create` | **всем** | завести гильдию — проверяется, только если включён `guild.require-create-permission` |
| `aurumguilds.admin` | оператору | `/guild admin` — вмешательство в чужие гильдии, бонусы, `friendlyfire`, `reload` |

`/guild`, `/party`, `/p`, `/g` и все их подкоманды, кроме `admin`, **прав не
требуют**.

### AurumAuth

| Узел | По умолчанию | Что даёт |
| --- | --- | --- |
| `aurumauth.admin` | оператору | зонтичное: включает все восемь подкоманд ниже |
| `aurumauth.admin.reset` | оператору | выдать токен смены пароля |
| `aurumauth.admin.info` | оператору | сведения об аккаунте |
| `aurumauth.admin.unlock` | оператору | снять блокировку по неудачным попыткам |
| `aurumauth.admin.logout` | оператору | выкинуть на экран входа, погасить сессию |
| `aurumauth.admin.history` | оператору | история входов |
| `aurumauth.admin.unregister` | оператору | снять регистрацию |
| `aurumauth.admin.2fa` | оператору | выключить двухфакторку потерявшему телефон |
| `aurumauth.admin.reload` | оператору | перечитать тексты сообщений |
| `aurumauth.admin.info.ip` | **никому** | видеть в `/auth info` адрес последнего входа |
| `aurumauth.bypass` | **никому** | входить без пароля |

`/login`, `/register`, `/reset`, `/2fa`, `/unregister` **прав не требуют** — и
не должны, иначе игрок не сможет войти.

**`aurumauth.admin.info.ip` намеренно не входит в зонтичное право.** Адрес — это
сведения о человеке, а не о сервере; он выдаётся отдельно и осознанно, а не
заодно с остальным администрированием.

**`aurumauth.bypass` — самое опасное право в проекте.** Оно ничего не делает,
пока в `config.yml` не включён `login.permission-bypass` (по умолчанию
выключен). Включать его на offline-сервере нельзя: UUID там вычисляется из
ника, значит любой, кто подключится под ником администратора, получит и его
UUID, и его группу в LuckPerms — вместе с правом обойти пароль. Настройка,
задуманная как удобство, превращается в способ зайти админом.

### AurumCompanion

Прав не объявляет вовсе. `/ticket` и `/webtoken` доступны всем — это
задумано: тикет должен уметь написать любой, а `/webtoken` и так работает
только после входа и выдаёт одноразовый код.

## Настройка

### Группа default

Ничего выдавать не нужно: игровые команды и так открыты всем. Явные запреты —
на случай, если право однажды приедет наследованием из другой группы или из
другого плагина.

```
/lp creategroup default
/lp group default permission set aurumguilds.admin false
/lp group default permission set aurumauth.admin false
/lp group default permission set aurumauth.admin.info.ip false
/lp group default permission set aurumauth.bypass false
```

> **Не ставьте группе `-*` или `permission set * false`.** Это отберёт и
> `/login` с `/register`, и на сервер никто не зайдёт — включая вас.

### Группа vip

VIP наследует всё от `default`, а из наших плагинов ему добавить нечего, кроме
права заводить гильдии — если вы решите сделать это привилегией.

```
/lp creategroup vip
/lp group vip parent add default
/lp group vip meta setprefix 50 "&6[VIP] &r"
```

Чтобы гильдии заводили только VIP, сначала в
`plugins/AurumGuilds/config.yml`:

```yaml
guild:
  require-create-permission: true
```

затем `/guild admin reload` и:

```
/lp group vip permission set aurumguilds.create true
/lp group default permission set aurumguilds.create false
```

Обычные игроки при этом **по-прежнему вступают в гильдии, состоят в них и
пользуются всем остальным** — ограничение касается только создания.

> **Prefix, а не suffix.** AurumGuilds вешает на группу гильдии узел `suffix` с
> приоритетом **100**. Если VIP тоже поставить suffix, победит тот, у кого
> приоритет выше, и тег гильдии либо исчезнет, либо перекроет метку VIP.
> Prefix с этим не спорит — он с другой стороны ника. Если suffix для VIP всё
> же нужен, ставьте приоритет заведомо ниже ста и проверьте вид в чате.

### Группа admin

```
/lp creategroup admin
/lp group admin parent add vip
/lp group admin permission set aurumguilds.admin true
/lp group admin permission set aurumauth.admin true
```

Зонтичное `aurumauth.admin` включает все восемь подкоманд — перечислять их по
одной не нужно.

**Адрес последнего входа выдавайте отдельно и не всем:**

```
/lp user <ник> permission set aurumauth.admin.info.ip true
```

Лучше конкретному человеку, чем группе: право на чужие персональные данные не
должно приезжать вместе с должностью.

**`aurumauth.bypass` не выдавайте никому.** Ни группе, ни пользователю. Если
однажды понадобится — сначала прочитайте раздел про него выше.

## Группы гильдий: их трогать не нужно

AurumGuilds заводит в LuckPerms **свою группу на каждую гильдию** — с
техническим именем вида `guild_17`, где 17 это внутренний номер гильдии (не
тег: тег меняется и содержит что угодно, вплоть до кириллицы, а имя группы
должно быть постоянным).

Что происходит само:

- гильдия создана — группа заведена, на неё повешен один узел `suffix` с тегом;
- игрок вступил — получил наследование от этой группы, суффикс пришёл сам;
- вышел или выгнан — наследование снято;
- гильдия распущена — группа удалена.

**Ни игрокам, ни лидерам, ни вам команд LuckPerms для этого вводить не нужно.**
В `/lp listgroups` эти группы будут видны — это нормально, удалять их вручную
не надо: удалите группу живой гильдии, и её участники останутся без тега до
следующего изменения состава.

Не давайте `guild_*` группам никаких прав. Они существуют ради одного суффикса;
любое право, выданное такой группе, достанется всей гильдии и исчезнет вместе с
ней при роспуске.

## Проверка

```
/lp group default info
/lp group vip info
/lp group admin info
/lp user <ник> permission check aurumauth.bypass     # ожидается false
/lp user <ник> permission check aurumguilds.admin
```

В игре: зайдите обычным игроком и убедитесь, что работают `/login`,
`/register`, `/guild help`, `/party create`, `/ticket`, а `/guild admin`
отвечает отказом. Если `/guild admin` **не** отказал — проверьте, не оператор
ли этот игрок: `default: op` у права означает, что оператору оно достаётся в
обход LuckPerms.
