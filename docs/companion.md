# Companion-плагин для модуля Minecraft

Модуль Minecraft работает и без плагина: игроки, кик, бан, whitelist и команды
идут через RCON. Но у RCON есть предел — он отдаёт только текст, и у игрока нет
способа написать в панель. Плагин закрывает обе дыры и работает **в две стороны**:

```
   панель  ──── HTTP (токен) ────►  плагин     список игроков, инвентарь
 10.0.0.1                          10.0.0.2

   панель  ◄─── HTTP (токен) ────   плагин     /ticket от игрока
```

| Возможность | Без плагина | С плагином |
| --- | --- | --- |
| Список игроков | ники (разбор ответа `list`) | + UUID, пинг, здоровье, мир, координаты |
| Аватары Crafatar | заглушка из двух букв | настоящий скин по UUID |
| Инвентарь игрока | недоступен | сетка предметов, броня, вторая рука, зачарования |
| Обращение игрока | нет способа | команда `/ticket <сообщение>` |
| Ответ модератора | только в панели | приходит игроку в чат через RCON `tell` |

Исходники плагина — в каталоге `companion-plugin/` этого репозитория.

## Сборка

```bash
cd companion-plugin
./gradlew :paper:jar      # или: gradle :paper:jar
# готовый файл: paper/build/libs/AurumCompanion-0.1.0.jar
```

Модуль `:paper` требует **JDK 25** — Paper 26.x собран под него. Логика плагина
(HTTP, JSON, клиент тикетов) вынесена в модуль `:core`, который не зависит от
Bukkit, собирается любым JDK ≥ 21 и покрыт юнит-тестами:

```bash
gradle :core:test
```

## Установка через Pterodactyl

1. **Выделите порт плагину.** В админке Pterodactyl: *Servers → ваш сервер →
   Build Configuration → Additional Allocations* — добавьте allocation с IP
   адреса туннеля (`10.0.0.2`) и свободным портом, например `8085`.
   Наружу этот порт светить нельзя: доступ к нему равносилен доступу к
   инвентарям игроков, как и к RCON.
2. **Залейте jar.** *File Manager → plugins/* → загрузите `AurumCompanion-0.1.0.jar`.
   Через SFTP то же самое: реквизиты в *Settings → SFTP Details*,
   каталог `/plugins`.
3. **Запустите сервер один раз** — плагин создаст `plugins/AurumCompanion/config.yml`.
4. **Заполните config.yml** (там же, в файловом менеджере):

   ```yaml
   token: <вывод openssl rand -base64 32>
   http:
     bind: "0.0.0.0"   # внутри контейнера; наружу порт выпускает allocation
     port: 8085        # совпадает с secondary allocation
   panel:
     base-url: "http://10.0.0.1:3001"   # внутренний адрес панели, не публичный домен
     server-id: "<UUID сервера из адресной строки панели>"
   tickets:
     cooldown-seconds: 10
   ```

   Токен должен быть ASCII (вывод `openssl rand -base64 32` подходит) и не короче
   16 символов: он уходит в HTTP-заголовок, а заголовки не принимают кириллицу.
   Пока в поле стоит `CHANGE_ME`, HTTP-сервер плагина не поднимется — это защита
   от случайного выхода в сеть с предсказуемым секретом.

5. **Перезапустите сервер.** В консоли должно появиться:
   `HTTP-сервер companion слушает 0.0.0.0:8085`.
6. **Пропишите то же в панели.** Сервер → настройки модуля (право
   `minecraft.configure`, только ГМ): адрес `http://10.0.0.2:8085` и тот же токен.
   В панели он хранится зашифрованным.

После этого вкладка «Инвентарь» станет рабочей, в списке игроков появятся
аватары, пинг и координаты, а команда `/ticket` начнёт создавать тикеты.

## Контракт HTTP (панель → плагин)

Авторизация: `Authorization: Bearer <token>`. Ответы — JSON, UTF-8.

### `GET /players`

```json
{
  "players": [
    {
      "uuid": "8667ba71-b85a-4004-af54-457a9734eed7",
      "name": "Steve",
      "health": 18.5,
      "maxHealth": 20,
      "world": "world",
      "x": 100.26, "y": 64, "z": -200.5,
      "ping": 42
    }
  ]
}
```

### `GET /players/{uuid}/inventory`

```json
{
  "items": [
    {
      "slot": 0,
      "id": "minecraft:diamond_sword",
      "count": 1,
      "displayName": "Гроза",
      "enchantments": { "minecraft:sharpness": 5 },
      "lore": ["Легендарный клинок"]
    }
  ],
  "armor": [ { "slot": 3, "id": "minecraft:diamond_helmet", "count": 1, "displayName": null, "enchantments": {}, "lore": [] } ],
  "offhand": { "slot": 0, "id": "minecraft:shield", "count": 1, "displayName": null, "enchantments": {}, "lore": [] }
}
```

Нумерация как в Minecraft: `0–8` хотбар, `9–35` основной инвентарь, броня — 4
слота, `offhand` — предмет или `null`. Пустые слоты в ответе не передаются.
Игрок не в сети — `404`.

### `POST /players/{uuid}/inventory/{slot}`

Тело `{"id":"minecraft:stone","count":3}` кладёт предмет в слот `0–35`;
пустое тело или `{"id":null}` — очищает слот. Неизвестный материал — `404`.

## Контракт HTTP (плагин → панель)

### `POST /api/internal/minecraft/servers/{serverId}/tickets`

Тем же токеном. Вызывается командой `/ticket` и попадает в core-сервис
`createOrAppendTicket`, поэтому действует общее правило: **один открытый тикет
на пару (сервер, игрок)**, повторное обращение дописывается в него же.

```json
{ "playerUuid": "…", "playerName": "Steve", "text": "меня загрифили" }
```

Ответ `{ "ticketId": "…", "created": true }` — по полю `created` плагин выбирает,
что написать игроку: «Тикет создан» или «Сообщение добавлено к твоему тикету».

Эндпоинт принимает запросы **только из приватной сети** (10.x, 172.16–31.x,
192.168.x, loopback) и наружу через nginx не публикуется.

## Что делает плагин на стороне игры

- **Основной поток.** Bukkit API не потокобезопасен, а HTTP-обработчики живут на
  своих потоках, поэтому каждое обращение к игре переносится в основной поток и
  ждёт результата не дольше 3 секунд — зависший сервер не подвесит панель.
- **Команда `/ticket`.** Сетевой запрос уходит асинхронно: блокировать основной
  поток на время HTTP-вызова нельзя, иначе лагает весь сервер.
- **Кулдаун.** Пауза между обращениями одного игрока (по умолчанию 10 секунд),
  чтобы чат нельзя было заспамить тикетами.
- **Секреты.** Токен не пишется в логи; в сообщениях об ошибках нет ни токена,
  ни адреса панели.

## Известные ограничения

- Инвентарь доступен только для игроков **в сети**: панель преобразует ник в UUID
  по текущему списку онлайн.
- `POST` на изменение слота реализован для основного инвентаря (0–35); брони и
  второй руки он пока не касается.
