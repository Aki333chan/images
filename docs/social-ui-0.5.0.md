# AurumUI 0.5.0 — гильдии и пати

## Установка

Сервер: заменить старые JAR на AurumGuilds-0.3.0.jar и AurumCompanion-0.5.0.jar,
затем перезапустить сервер. На клиенте заменить мод на AurumUI-0.5.0.jar.
Minecraft 26.2, Fabric Loader 0.19.5+, Fabric API для 26.2, Java 25.
Старые версии тех же плагинов не должны одновременно лежать в plugins/.
Изменение схемы базы не требуется. Существующие языковые файлы сохраняются;
новые ключи берутся из встроенных переводов.

Companion включает upstream cdebb2c: HTTP-статус тюрьмы офлайн-игрока EssentialsX.

## Меню U

Гильдия: существующие гильдии, состав, статус онлайн, настройки для просмотра,
бонусы, входящие приглашения. Создание, принятие приглашения, выход.
Любой участник может внести указанную сумму в банк и открыть журнал в чате.
Снятие доступно согласно настройке банка.

Офицер: приглашение из списка видимых онлайн-игроков, исключение младшего ранга.
Лидер: также повышение/понижение, передача лидерства, тег, режим вступления,
дружественный огонь, доступ к банку, описание, роспуск.
Параметры с фиксированными значениями выбираются кнопками.

Пати: создание, список приглашений, принятие, состав, приглашение из онлайна,
выход. Любой участник приглашает; только лидер исключает и передаёт руководство.

## Администратор

Нужны одновременно aurumui.admin и aurumguilds.admin. При '*' уже доступны.
Обычным игрокам эти права выдавать не нужно.

В списках доступны все гильдии/пати. Дополнительные действия: принудительное
исключение, передача лидерства гильдии, роспуск, диагностика выбранной группы.
У гильдий также меню бонусов: выбрать вид, установить величину и срок или снять.
Сроки: 30m, 2h, 7d; 0 означает постоянно. Значение ограничивается сервисом бонусов.
Административные изменения записываются в журнал сервера.

## Переход между гильдиями

Теперь приглашение может прийти игроку, уже состоящему в другой гильдии.
Первое принятие только предупреждает, повторное принятие ТОЙ ЖЕ гильдии в
течение 30 секунд подтверждает переход. В UI появляется окно подтверждения.
Команда /guild join [имя] использует тот же механизм: подтверждение общее с UI.
После истечения срока или смены адресата нужно подтвердить заново.
Лидер сначала передаёт лидерство либо явно распускает свою гильдию.

MariaDB обновляет единственную строку членства атомарно. Если запись не удалась,
старое членство и приглашение сохраняются. Первичный ключ UUID не допускает
одновременного членства в двух гильдиях. Новый ранг — участник; старые доступы
LuckPerms/WorldGuard снимаются штатными hooks, новые выдаются ими же.

## Проверка

106 тестов core гильдий, 10 тестов Paper (права, авторизация, банк, локализации),
155 тестов Companion, включая новый HTTP endpoint. Все прошли.
Fabric-мод собран Java 25. Игровая визуальная проверка и интеграционный прогон
на живом Paper/MariaDB не проводились; тест передачи проверяет сервис и отказ
хранилища, но не заменяет проверку реального MariaDB/Vault/LuckPerms/WorldGuard.

После установки проверить с двумя обычными аккаунтами: приглашение, переход,
снятие старых доступов, взнос, запрет чужого управления. Для лидера — передача
руководства; для администратора — выбранная гильдия, бонусы и диагностика.

## Публикация addons

Копии: guilds-v0.3.0.jar и companion-v0.5.0.jar. Клиентский мод распространяется
отдельно и не устанавливается серверной панелью как Bukkit-плагин.
Для обнаружения панелью требуются опубликованные GitHub Releases с тегами
guilds-v0.3.0 и companion-v0.5.0, по одному исполняемому JAR в assets.
В assets удобнее использовать AurumGuilds-0.3.0.jar / AurumCompanion-0.5.0.jar:
так панель распознаёт установленный плагин по имени файла.
Один коммит файлов в корень addons не делает их доступными установщику панели.
