# Зоны 7DTD — состояние и следующие этапы

## Первый этап: 1.0.13-rc.1

Реализованы пять пресетов: safe, information, sanctuary, bonus, custom.
Рисование двумя углами, живое редактирование, запрет PvP, защита игроков от урона,
раздельное удаление при спавне/существующих зомби и животных, сообщения, один бонус.
Панель проксирует авторизованные запросы; источник правил — файл текущего мира
Companion. Ревизия и worldId защищают запись; старый мод не заявляет zones-v1.

Это первый инкремент, не весь набор одобренных сценариев. Нативные ограничения
ещё требуют живых проверок: сборка по V3.2b10 не подтверждает поведение клиента.
Удаление после спавна не является предотвращением создания объекта движком.
Турели/взрывчатка/исчезнувший атакующий требуют проверки владельца урона.
При runtime-ошибке зоны отключаются с диагностикой, а краткие баффы истекают.

## Второй этап: 1.0.14-rc.1

Команды входа/выхода, выключенные по умолчанию: buffplayer/debuffplayer/teleportplayer,
только текущий {player}, до 4 на событие. Отдельные cooldown и лимит 8 команд/сек;
никаких очередей/авторетраев, событий при логине/респавне/сохранении нет. Телепорты
имеют общую паузу игрока 10 секунд. Это не универсальный скриптовый движок CSMM.
zones-v2 и чтение старого файла с безопасными значениями; запись только нового формата.
Права zones.manage и zones.commands у ADMIN/GM; нет зависимости от configure (GM-only).
Длительные эффекты команд не снимаются гарантированно при логауте: использовать
временные баффы, для эффекта только в зоне — прежний бонус. Подробности в README.
Исправлен прямой доступ к publicized-полям пакета урона: используется инъекция
Harmony для фактически private-полей исходной игры. Живой PvP-тест всё ещё нужен.

## Дальше по порядку (живые проверки отложены владельцем)

Владелец подтвердил разделение защиты окружения и действий игроков. Риск повторной
добычи при простой серверной отмене изменений блоков остаётся основанием для
отдельного этапа: [BLOCK-PROTECTION-AUDIT.md](BLOCK-PROTECTION-AUDIT.md).

1. Полные ограничения добычи/строительства игроками и LCB: сначала нативная
   синхронизация с обычным клиентом, без позднего возврата блоков и дюпа.
2. Более тонкие категории существ и настоящая отмена спавна — только после
   проверки серверных путей и освобождения объектов. Настраиваемая сила/несколько бонусов.
3. Общий живой прогон SMOKE-TEST.ru.md, включая защиту блоков, расписания, тюрьму/мероприятия, команды, границы PvP, турели,
   взрывчатку, типы существ, перезапуск и нагрузку. До него защиты остаются RC.

Админский клиентский мод и виртуальная экономика не нужны. Игроки ничего не ставят.
Другие ожидающие живого теста функции: офлайн-запись инвентаря, восстановление,
телепорты, наборы предметов и включение заготовок расписаний.

## Третий этап: 1.0.15-rc.1

Ограниченный вход по сочетанию списка ID и уровня, портал по наблюдаемому входу.
Пресеты/режим, выбор онлайн-игрока, X/Y/Z назначения, приоритет, cooldown, сообщение.
Старые файлы читаются с выключенным перемещением; HTTP требует zones-v3.
Используется прежний секундный проход, общий бюджет 8 действий и gate телепортов.
Запрет важнее портала, при равном приоритете — стабильный ID. Структурированные
назначения внутри любых включённых restricted/portal зон отклоняются: нет цепочек.
Native CanPlayersSpawnAtPos и границы мира проверяются перед переносом; чанк должен
быть загружен, ради порталов он не генерируется/не удерживается. Правки прочих полей
не блокируются из-за выгрузившейся прежней точки. Подробнее и ограничения в README.

Нюанс: возврат раз в секунду — не непроницаемая граница, транспорт не перемещается,
при недоступном назначении возврат пропускается. Пока не применять как строгую
охрану/тюрьму. Удержание внутри и более строгие реакции остаются следующим этапом.

## Четвёртый этап: 1.0.16-rc.1

Разделены prison и event. Prison: явные постоянные назначения с UTC-сроком или
ручным освобождением, переживают смерть/логаут/рестарт. Event: список участников,
удержание после наблюдаемого входа, освобождение при смерти/логауте/рестарте/выключении.
Не захватывают прохожих. Редактор на карте: онлайн-список, офлайн-ID, дата окончания,
освобождение по Save. Возврат внутри собственной зоны; неподходящие/перекрытые точки
отклоняются. Optional dismount/strict kick выключены по умолчанию. Подробные ограничения
и последовательность тестов — README и SMOKE-TEST.ru.md. Без тяжёлого планировщика:
прежний секундный проход, bounded online-state, сроки в ручной атомарной записи зон.
Схема zones-v4; новые поля старых файлов безопасно заполняются только при загрузке.
Это не античит, не защита блоков, не полное предотвращение выхода между проверками.
Реальные игровые проверки транспорта, смерти, телепортов и Harmony ещё не выполнены.

## Пятый этап: 1.0.17-rc.1

Расписание на зону: дни недели, часы (включая ночь), необязательные UTC-сроки,
явное фиксированное смещение без автоматического DST. Выключено по умолчанию.
Прежний секундный проход обновляет активность без дисковых записей и новых задач.
Переключение часов не имитирует вход/выход и не запускает команды, портал или
регистрацию event. Закрытие event освобождает; prison остаётся на персональных сроках.
Защита/бонусы/правила существ действуют только при активности. Геометрия назначений
проверяется независимо от расписания, чтобы следующее открытие не создало цепочку.
zones-v5, безопасное чтение старого файла; даты не сбрасываются после рестарта.
Карта показывает конфигурацию, без нового live-индикатора открытия. UI, API, Core
проверены автоматическими тестами; нативная сборка по V3.2b10, игровой smoke впереди.

## Шестой этап: 1.0.18-rc.1

Две независимые выключенные по умолчанию опции: прямой серверный урон блокам
от зомби/животных и от взрывов. Ранний перехват семейства обработчиков блока;
взрывы используют scoped hardness до callbacks разрушения, с finalizer очисткой.
Нет позднего возврата блоков и компенсаций инвентаря. Геометрия, перекрытия и
расписания используют прежние правила. zones-v6, безопасное чтение старых файлов.
Редактор переиспользует Save/ACL; английский, польский, русский. Нет новых зависимостей,
БД или обхода блоков. Клиентские действия, props, обрушение/POI reset не покрыты;
сами взрывчатые блоки расходуются штатно. Нативные игровые проверки ещё впереди.
