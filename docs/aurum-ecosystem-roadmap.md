# Aurum ecosystem roadmap

Этот файл обновляется после каждого законченного этапа. Верхний незавершённый
пункт — следующий в работе.

## Завершено

- [x] Архитектурная граница AurumCore, модулей и Companion.
- [x] Пассивный AurumCore 0.1.0: API, наблюдение Vault, placeholders, MariaDB
  migrations, локализации и полностью отключённые денежные записи.
- [x] Модель глобальной казны отдельно от общей денежной массы.
- [x] Расширяемая оболочка financial policies: налоги, сборы, комиссии,
  кешбэк, субсидии, лимиты, льготы и versioned custom handlers.
- [x] Проектирование гарантированного обмена через holds, TRADE_ESCROW,
  revision confirmations и восстанавливаемую saga/outbox.
- [x] Безопасное пространство команд: `/pay`, а администрирование только через
  `/aurum economy ...` (`/aurum eco ...` как внутренний алиас).
- [x] Ledger engine 0.2.0: атомарный MariaDB executor, блокировки счетов в
  стабильном порядке, idempotency, запрет отрицательного баланса, казна,
  money supply, аудит отказов, outbox и конкурентные тесты. Paper/Vault доступ
  к денежным записям пока намеренно не включён.
- [x] Shadow/migration 0.3.0: неизменяемые снимки Vault, чтение порциями без
  длительной нагрузки одного тика, отчёт расхождений, защищённый повторяемый
  import в неактивный ledger, verify и rollback CSV. Essentials/Vault остаются
  рабочим провайдером и не изменяются.
- [x] Публикационный контракт экосистемы: исходники и каталог панели находятся
      в `Images`, готовые JAR — в `Addons`, а установка панелью идёт только из
      GitHub Releases с отдельными тегами `<name>-v<version>`.
- [x] Единый пакет установки `Aurum Ecosystem` в панели: без ручного выбора,
      с пропуском уже установленных JAR, серверным графом зависимостей, установкой
      Core перед AddonsNPC и предупреждением об отсутствующем Vault/VaultUnlocked.
      Компоненты остаются отдельными JAR и релизами; Legacy-матрица записана в
      `docs/aurum-plugin-compatibility.md`.
- [x] Active economy 0.4.0: AurumCore — авторитетный MariaDB ledger и
  VaultUnlocked-провайдер; безопасный cutover gate, кэшированные чтения,
  атомарные записи, `/pay`/`/apay`, баланс, казна, give/take/set, права,
  лимиты, причины, локализации и умное tab completion.
- [x] Policy engine 0.5.0: цепочка TAX/FEE/COMMISSION/CASHBACK/SUBSIDY,
  LIMIT и EXEMPTION; расписание и условия, YAML bootstrap/import, управление
  командами, неизменяемые DB revisions и атомарный аудит сумм каждого правила.
- [x] Multi-currency и exchange engine 0.6.1: до 16 валют, одна primary-валюта
  для Vault, native API для остальных, курсы/комиссии/лимиты/расписания/условия,
  ревизии котировок, атомарный обмен и безопасный повтор после истечения котировки.
- [x] Durable holds 0.7.0: резерв полного списания с учётом policy, защита
  доступного баланса от параллельных трат, атомарные capture/release, TTL и
  безопасное восстановление capture после потерянного ответа MariaDB.
- [x] Core 0.10.0 hardening: расчёт trade больше не блокирует общий DB executor;
  двусторонние денежные оферты сворачиваются в одну net-проводку; SETTLING
  восстанавливается после рестарта; сделка завершается только после записи всех
  item-claims. Повтор hold с тем же ключом, но другим намерением отклоняется.
  Claim lease проверяется до finish, settle требует полный cursor, нейтральный
  `pause` не расходует попытку, TTL продления берётся из конфигурации.
- [x] Core 0.11.0: исходящее помещение предмета на trade-стол закрыто PDC receipt.
  Изменённый инвентарь и полная оферта сначала сохраняются вместе в `player.dat`,
  затем migration 9 атомарно пишет оферту и idempotency marker в MariaDB. Потерянный
  ответ повторяет тот же ключ, окончательный отказ создаёт долговечный return-claim.
  Проверяется конкретный cursor/slot, а recovery запускается только для игроков с receipt.
- [x] AddonsNPC 1.9.0: магазины, скупщики и торговцы бонусами переведены с прямых
  Vault-записей на holds; добавлен `transactions.yml` и периодическое recovery.
- [x] AurumSlots 1.4.0: денежные ставки переведены на holds и native API;
  выплаты и аварийные возвраты идемпотентны, а физический gold-only режим не требует Core.
- [x] AurumArena 1.5.0: ставки, выплаты, возвраты и чемпионский пул переведены на holds
  и native API. Касса ставок и призовой пул — разные счета. Комиссия стала настраиваемой
  проводкой: в казну сервера или в чемпионский пул, со ставок всегда, с пула по выбору.
  JAR собран; релиз в Addons ещё не выпущен.

## Осталось — в порядке выполнения

1. [x] Перевести AurumGuilds на native API: счёт `GUILD:<id>`, взносы, снятия и роспуск
   с ненулевым балансом (0.4.0). Holds не понадобились — обе стороны операции денежные,
   хватает атомарной `transfer`. Бонусы за счёт казны переводить было нечего: они
   денег не трогают.
2. [x] Усилить предметную часть saga до полноценного claim/quarantine-хранилища.
   Слой доставки реализован в Core 0.8.0 (`AurumClaimApi`, `aurum_claims`, migration 8,
   `/aurum claims`), все потребители AddonsNPC переведены в 2.0.0 — магазины, скупщики и
   гильдейские торговцы. Следующий потребитель — гарантированная торговля.
3. [~] Реализовать гарантированный player trade (Core 0.9.0): машина состояний с
   ревизиями, изъятие предметов в запись, расчёт денег через holds, возврат и выдача
   заявками, команды `/trade` и окно одной сделки — оболочка над тем же сервисом.
   Денежный конвейер и recovery усилены в 0.10.0, обе item-границы закрыты receipts
   в 0.10.0/0.11.0. `trading.enabled: false` остаётся безопасным дефолтом до живого
   Paper + MariaDB fault-injection прогона; unit-тестами покрыты idempotency и запрет
   повторного применения либо переиспользования ключа для другой оферты.
4. [x] Подключить AurumUI: баланс, переводы, сделки, казна и админские формы.
   Сделано (AurumUI 0.7.0 + Companion 0.8.0 + Core 0.13.0): вкладка «Экономика» —
   баланс по валютам и перевод игрока, у администратора казна с денежной массой и
   налогами, поиск игрока и give/take/set с причиной. Игрок может пригласить в
   гарантированную сделку, принять её, открыть защищённый предметный стол, задать
   денежную оферту и подтвердить показанную ревизию. Администратор видит карантин
   долговечных выдач, повторяет либо осознанно списывает запись с подтверждением.
   Асинхронные снимки проходят через Companion без `join` на Paper thread и без
   нового фонового polling; запросы идут при открытии, действии и ручном refresh.
   Это приоритет: повседневное администрирование экономики живёт в игре, рядом с
   тем, кому выдают. Админский канал уже есть и сделан правильно — набор scope'ов
   (`ADMIN_ARENA`, `ADMIN_NPC`, `ADMIN_SLOTS`) вычисляет сервер из
   `player.hasPermission`, клиент его не сообщает, и каждый запрос проверяется
   отдельно. `ADMIN_ECONOMY` добавляется по тому же образцу.
   Права раздаются узлами `aurum.admin.economy|policy|exchange|claims|migrate`
   через LuckPerms. `default: op` — это дефолт, а не способ раздачи: OP обходит
   любой плагин прав, а выдают его обычно ради `/gamemode`.
5. [~] Переделать Companion и веб-панель с Vault-summary на AurumCore API.
   Сделано (Core 0.12.0 + Companion 0.11.0): доска богатства одним запросом к ledger
   (`AurumEconomyApi.richest`), баланс и общая картина из Core при `EconomyMode.ACTIVE`
   и отдельные fail-closed маршруты панели без Vault fallback. В панели плитки
   денежной массы, казны, налогов и Richest живут во вкладке экономики, а не среди
   CPU/RAM. Deposit/withdraw используют нативные проводки
   `ADMIN_ADJUSTMENT` с автором, причиной и ключом идемпотентности; Core migration 10
   связывает ключ с полным intent и отклоняет его повторное использование.

   Область панели — правила и разбор задним числом, а не повседневные выдачи:
   ставка налога действует на всех сразу и назад не чинится, а у панели есть роли,
   2FA, журнал с автором и возможность показать изменение до применения. Разделение
   с AurumUI записано в `docs/aurum-core-architecture.md`.

   Осталось, в порядке выполнения:

   5.1. [x] Native deposit/withdraw/set поверх `AurumEconomyApi`: ключ создаёт панель и
        сохраняет для retry, причина/автор/категория передаются явно, ошибки приходят
        кодами, денежная запись требует `minecraft.economy.admin`. При активном Core
        timeout никогда не переключает запись на Vault. В Core 0.16.0 абсолютный `set`
        стал отдельным compare-and-set: панель передаёт показанный expected и target,
        MariaDB сравнивает и проводит под одной блокировкой, а terminal conflict хранится
        под тем же ключом. Повтор потерянного ответа не затирает более позднюю проводку;
        ноль и no-op поддержаны.
   5.2. [x] Экраны чтения веб-панели (Core 0.14.0 + Companion 0.9.0): оборот,
        эмиссия/изъятие, налоги, ограниченная история ledger с индексированным
        фильтром по stable account key, политики, курсы, holds и карантин заявок.
        Раздел закрыт правом `minecraft.economy.view`, не имеет Vault fallback,
        свёрнут по умолчанию и обращается к БД только при явном открытии/refresh.
   5.3. [x] Редактор правил (Core 0.15.0 + Companion 0.10.0): ставки налогов,
        комиссии и курсы меняются двухфазно. Preview валидирует полную замену,
        ожидаемую immutable-ревизию и выдаёт короткоживущий actor-bound токен;
        apply атомарно сохраняет следующую ревизию только с причиной. Конфликт
        никого не перезаписывает, потерянный успешный ответ не допускает повторной
        записи, Vault fallback и polling отсутствуют. Аудит и редактор оформлены
        отдельной capability-вкладкой Minecraft-модуля; без включённого AurumCore
        она не появляется. В 0.11.0 туда же перенесены общая сводка и Richest;
        карточка игрока сохранена для точечной работы с online/offline UUID.
        MODERATOR только читает, ADMIN изменяет, OWNER/GM получает wildcard.
   5.4. [ ] Мультивалютность в панели. **Отложено намеренно**: одной валюты
        сейчас более чем хватает, многовалютность в Core — задел на будущее.
        Следствие записано, чтобы не искать его заново: Vault знает только
        primary-валюту (`AurumVaultEconomy` строится именно на ней), поэтому
        работать с остальными панель сможет **только** через маршруты из 5.1.
6. [~] Для выдачи/изъятия AddonsNPC, выдачи trade и помещения предмета на стол добавлен
   crash receipt в PDC:
   инвентарь и receipt сохраняются одним `player.dat` до продвижения MariaDB cursor,
   либо idempotent offer-write, поэтому retry не повторяет предметный эффект. Для команд
   оферт AddonsNPC 2.1.0 фиксирует два явных режима: at-most-once с cursor-before-effect
   по умолчанию и повторяемый `idempotent:` с обязательным ключом получателя. Остался
   Paper fault-injection; встроенные предметные операции и программный контракт команд
   закрыты в коде.
7. [~] Роспуск гильдии использует persisted plan для `leader/split/treasury/keep`:
   политика и получатели заморожены, выплаты и аудит отмечаются атомарно, незаконченный
   план возобновляется после рестарта, а гильдия до конца заблокирована от изменений.
   Чтение ledger Companion не блокирует Paper thread. Выплаты в активном Core используют
   stable keys; Vault fallback принципиально не даёт exactly-once payout. Остался живой
   fault-injection незавершённого плана.
8. [ ] Опционально мигрировать динамические настройки арен, NPC, автоматов и
   связей гильдий. WorldGuard остаётся владельцем самих регионов.
9. [ ] Полный staging-прогон Paper 26.2 + MariaDB + VaultUnlocked, нагрузка,
    сбои БД/рестарты, Spark и финальная инструкция переключения Essentials.
