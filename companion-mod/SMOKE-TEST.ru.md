# Aurum Companion 7DTD — проверка 1.0.12-rc.1

## Добавление и замена (новый живой тест)

1. Установить 1.0.12 при остановленном сервере, сохранив companion.cfg; запустить.
2. На тестовом персонаже оставить пустой слот рюкзака и отдельный предмет с модами;
   записать их состояние и соседние предметы/прогресс, выйти, подождать 5 секунд.
3. Открыть сохранение, выбрать пустой слот → «Добавить или заменить предмет».
   Найти камень/патроны, выбрать 5 штук, записать. Качество для них не показывается.
4. Через 5 секунд обновить снимок, проверить предмет, копию .ttp.aurum-*.bak и аудит.
5. В занятом слоте выбрать пистолет, качество 6, количество 1. Без галочки замены
   кнопка неактивна. После подтверждения запись заменяет весь старый экземпляр,
   включая его моды; соседние вещи не меняются. Войти и проверить всё в игре.
6. Онлайн-игрок, устаревшая ревизия, неподдерживаемый файл и неверное количество/
   качество должны давать отказ. Потерянный ответ не запускает повтор записи.
7. ADMIN/GM имеют edit; пользователь без edit не может писать прямым POST.
   Пользователь с edit без give может искать и заменять офлайн, но не выдавать онлайн.
8. Проверить восстановление и нагрузку по инструкции ниже. Не считать компиляцию
   и автотесты заменой реального теста .ttp и повторного входа.

Офлайн-просмотр и выдача подтверждены владельцем на сервере 2026-09-20.
Ниже новый тест записи, который ещё не выполнен в игре.

## Уменьшение и удаление стаков (тестовый игрок)

1. Обновить мод при остановленном сервере, сохранить companion.cfg. Запустить сервер.
2. У тестового игрока оставить известный стак (например, 10 камней) в рюкзаке,
   записать остальные предметы/качество/модификации и прогресс, затем выйти.
3. Через 5 секунд открыть сохранённый инвентарь. Выбрать стак, указать «Оставить» 7,
   отметить подтверждение, нажать «Уменьшить». Должно быть «Сохранено».
4. Проверить копию `<ID>.ttp.aurum-<requestId>.bak` в папке Player и аудит панели.
   Через 5 секунд обновить снимок: 7 предметов. Войти в игру и проверить количество,
   соседние слоты, броню, прогресс, квесты и модификации: они должны сохраниться.
5. Пока игрок онлайн, запись из ранее открытого снимка должна отказать. После выхода
   и нового сохранения старый снимок также не должен подходить: нужно обновление.
6. Повторить с нулём (удаление стака), отдельно проверить пояс. У модератора без
   `sevendays.inventory.edit` кнопок нет, POST должен быть запрещён.
7. При «не поддерживается» не обходить защиту: сообщить результат. Это может быть
   round-trip, размер >1 MiB или файловая система. При «результат неизвестен» сначала
   перечитать сохранение, не повторять удаление вслепую. Никаких автоматических повторов.
8. Проверить CPU/FPS во время одиночного изменения; весь commit синхронный.
9. Для проверки восстановления только на тестовом игроке: остановить сервер,
   отдельно сохранить текущий `.ttp`, вернуть нужную копию как основной `.ttp`, запустить.
   Это вернёт весь прогресс игрока к моменту той копии, не только предметы.

Панель: карта ~25% ниже, не выше ~55% окна; drag/zoom/клик по приватам должны работать.
Журнал событий первоначально свёрнут, раскрытие показывает максимум 5 записей,
фильтр работает; сворачивание не удаляет события из базы.

## Новый этап: офлайн-просмотр

После обновления мода (конфиг сохранить) откройте Игроки → Сохранённые игроки.
1. Под тестовым игроком положить разные предметы в пояс/рюкзак, надеть броню,
   затем штатно выйти. Не останавливать игровой сервер.
2. Подождать завершения сохранения и ещё 5 секунд. Найти игрока по имени или ID,
   открыть сохранение. Проверить предметы, качество, количество, пустые слоты,
   дату сохранения. Кнопки выдачи здесь быть не должно.
3. Войти этим игроком, нажать Обновить в панели: отказ вместо устаревшей сетки.
   В онлайн-списке прежний просмотр должен продолжать работать.
4. Проверить поиск, страницы, закрытие и мобильную ширину. У пользователя без
   `sevendays.inventory.view` списка нет, оба API должны возвращать 403.
5. Замерить FPS/CPU во время одного открытия реального сохранения. Фоновый опрос
   сохранений не предусмотрен. На старом Companion ожидается просьба обновить мод.
6. Ничего не редактируется; специальные проверки повреждённого файла/`.tmp` делать
   только на отдельной тестовой копии, не портить действующее сохранение ради теста.

Автотесты и сборка с целевыми DLL не заменяют этот живой тест.

Это тестовая серверная сборка под предоставленные DLL V3.2.0 (b10).
Компиляция и автоматические тесты выполнены; запуск внутри настоящего сервера
этой новой сборки ещё не проверен. В предыдущей 1.0.1-rc.1 владелец подтвердил
связь панели с модом и создание тикетов. Не считать это проверкой новой сборки.
В ModInfo.xml версия числовая 1.0.12: загрузчик игры не принимает semver-суффикс RC
как System.Version. ZIP, DLL informational version и лог содержат 1.0.12-rc.1.

## Установка для проверки

1. Остановить тестовый сервер. Сохранить предыдущую папку мода, если она есть.
2. Распаковать папку AurumCompanion из ZIP в Mods. Не оставлять две копии этого мода.
3. Сохранить свой companion.cfg; если его ещё нет, скопировать companion.cfg.example
   в companion.cfg и заполнить panel-url, server-id и token из настроек модуля 7DTD панели.
4. Порт 8110 доступен только панели по приватной сети/туннелю, не интернету.
   В Pterodactyl адрес слушателя должен существовать внутри контейнера.
   127.0.0.1 доступен только из того же сетевого namespace, а не с другой машины.
5. Для русского чата добавить `language = ru` в сохранённый companion.cfg;
   для польского — `language = pl`. Без строки используется английский.
6. Запустить сервер. Ожидается `[AurumCompanion] 1.0.12-rc.1 готов.`
   Не должно быть TypeLoadException, MissingMethodException или ошибок регистрации событий.

Клиентам ставить этот мод не требуется. Harmony для нынешних функций не нужен.
Совместимость с console crossplay и конкретным EAC-режимом не подтверждена.
Не менять настройки защиты/crossplay вслепую ради этой сборки.

## Что проверить

- Выдача 1.0.9: ADMIN/GM → Игроки → Инвентарь → Выдать предметы. Найти `ammo`,
  выбрать позицию в прокручиваемом списке, указать количество и нажать «Выдать».
  Причина и дополнительное подтверждение не нужны. Проверить
  появление на земле и ручной подбор. Это НЕ доставка в рюкзак, другие могут забрать вещи.
  Затем выдать одно оружие качества 6; случайных модификаций быть не должно.
- При полном рюкзаке вещь остаётся предметом мира; инвентарь не перезаписывается.
  Проверять на безопасном месте. Срок жизни до 5 минут, игровые лимиты могут убрать её раньше.
- Получатель выходит между поиском и выдачей: статус offline, без предметов.
  Двойной клик не создаёт второй запрос; неизвестный результат повторять только тем же ID.
  После перезапуска мода старый запрос отвергается. Не отключать сеть живого сервера ради теста.
- MODERATOR без sevendays.inventory.give не видит выдачу и получает отказ прямого POST.
  Просмотр инвентаря сам по себе не даёт права выдавать. В аудите есть получатель,
  предмет, количество, качество, автоматическая пометка `Panel item grant`, ID запроса и отдельный результат.

- Карта: выбрать приват/POI/игрока, закрыть описание крестиком. Выделение снимается,
  положение и масштаб карты сохраняются; мышь, клавиатура и сенсор работают.
- Сетка 1.0.8: проверить пустые и занятые слоты, открыть карточку предмета,
  закрыть её крестиком, обновить снимок. Старая карточка не должна остаться.
  С модом 1.0.7 видны только занятые ячейки и подсказка обновить мод.
- Инвентарь: ADMIN/GM → Игроки → Инвентарь. Сравнить пояс, рюкзак,
  экипировку, количество/качество и номер занятого слота с игрой. Переложить вещь,

  мгновенная актуальность; время «Получено панелью» не является временем снимка.
- Проверить выход игрока во время просмотра: после обновления вместо старых вещей
  должно появиться «не в сети». До первого снимка — отдельное сообщение, не пустой

- MODERATOR без sevendays.inventory.view не видит кнопку, прямой API запрещён.
  Другой сервер без выданного доступа также запрещён. Нет команд сохранения,

  регулярное падение FPS и нарастающая очередь запросов требуют профилирования.

  прямые запросы `/map` и `/map/tiles/...` без права также запрещены.
- Старый мод: предложение обновить, а не зависший пустой экран. Мир ещё грузится:
  сообщение загрузки. Нет mapinfo.json: видны маркеры и инструкция включения рендера.
- С включённым EnableMapRendering после посещения местности: проверить игрока и
  claim у узнаваемого здания, в том числе при отрицательных X/Z. Север вверху;
  клики показывают владельца и координаты. Перетаскивание, масштаб, выбор игрока,
  отключение слоёв, EN/RU/PL и узкий экран. В неизученных местах допустима сетка.
- Сверить MSPT/FPS/CPU без карты и с открытой картой; закрытие вкладки прекращает
  опрос. Проверить с двумя наблюдателями: временный map_busy допустим, очередь
  запросов не должна бесконечно расти. Истёкшие claims пока не помечаются отдельно.

- Сверить параметры орды с `gso true`: отключена, фиксированный и случайный
  интервал. Панель должна показывать сохранённую игрой дату, а не день % 7.
  Проверять изменение игровых настроек только на тестовом мире.
- Одно событие с одним eventId, отправленное дважды, создаёт одну строку.
  Разные eventId с одинаковым текстом создают разные строки. Старый companion
  без eventId остаётся рабочим, но защиты от дублей у него нет.
- Снимок мира может отставать до 2 секунд. До готовности мира панель показывает
  загрузку, не день 0. При недоступном расписании не должен появляться отсчёт 7 дней.

- Настройки подключения панели: EN/RU/PL, правильные статусы, полный UUID,
  список функций мода. Мод 1.0.2 должен отображаться как старый без списка функций,
  не как неработающий. Язык панели не должен менять язык игрового чата.
- `/help`, пустой `/ticket`, успешный `/ticket тест` и слишком частый повтор:
  сообщения и подпись отправителя на выбранном языке. Повторить с en/ru/pl
  после перезапуска. Ответы администратора остаются в исходном виде.
- `forward-chat = false` / `forward-deaths = false` убирают соответствующие
  возможности из /ping; не должны менять работу тикетов и личных ответов.

- Новые пределы: повторный /ticket или /report того же игрока до ответа не отправляет
  второй запрос. После ошибки можно повторить; после успеха действует старый cooldown.
- Параметры `http-max-requests`, `http-max-body-bytes`, `http-io-timeout-ms`,
  `ticket-max-pending` необязательны. Старый companion.cfg сохраняется.
- Неполный авторизованный HTTP body должен закрыться по таймауту, а следующая проверка
  /ping — работать. Запрос без токена с незавершённым body должен получить 401.
  Слишком большой body — 413, переполнение обработчиков — 503.
- Эти ограничения начинают работать после разбора заголовков HttpListener. Они не
  заменяют сетевую изоляцию, firewall и лимиты соединений: мод НЕ публичный HTTP-сервис.
- Проверка `http://10.0.0.2:8110/ping` с машины панели без токена должна вернуть 401.
  Токен не вставлять в публичные логи/скриншоты. В панели копировать полный server-id,
  не короткий ID Pterodactyl. Индикация «на связи» проверяет лишь направление панель → мод.

- Панель: Companion доступен, состояние мира, FPS и список игроков обновляются.
- В игре: `/ticket проверка связи`, `/report <ник> тест`; ответ модератора видит
  только адресат. Жалоба не должна появляться в общем чате.
- Обычный общий чат появляется в событиях панели; whisper/party/friends не передаются.
- Вход, выход, смерть игрока, PvP: правильные участники, без лавины событий от зомби.
- Объявление из панели появляется один раз. Подтверждение означает передачу пакета
  игровому сетевому слою, а не подтверждение отображения клиентом.
- Перезапуск сервера: мод запускается повторно без занятого порта/дублирования.
- На тестовом экземпляре: занятый listen-port приводит к чистому отказу запуска мода,
  а не оставляет работающий отправитель событий.

HTTP `/ping`, `/state`, `/players` требуют Authorization: Bearer <token>.
Не присылать токен в чат или логах. Для отчёта достаточно версии, результатов пунктов
и ошибок AurumCompanion без конфигурации.

## Известные ограничения этого этапа

- Нет карты и новых игровых команд: сейчас проверяется основа.
- Сетевое усиление ещё впереди: ранняя авторизация до чтения тела, лимит байтов,
  deadline чтения и ограниченная параллельность HTTP. До этого порт строго приватный.
- Защита ticket/report от нескольких одновременных отправок ещё впереди.
- События в памяти, не финансовый журнал; при рестарте/переполнении возможна потеря,
  при повторной доставке — дубли в панели. Deduplication будет отдельным этапом.
- Панель пока может неверно оценивать следующий Blood Moon при выключенной орде
  или случайном интервале. Факт текущей орды приходит от игры, прогноз требует правки.
- Ожидание игрового потока ограничено 2 секундами и 32 callbacks. HTTP 503/504 с
  game_operation_not_started означает отказ до выполнения; game_operation_outcome_unknown
  означает, что работа уже началась. Не повторять такие изменяющие запросы автоматически.
